# novayagazeta.ru - архив в Markdown

Скачивание всех статей novayagazeta.ru в Markdown вместе с изображениями из них. Медиафайлы других типов (видео, вставки сервисов) не скачиваются.

Сайт объявил, что 9 ноября 2026 года погасит серверы, так что архив - это гонка с этой датой. Собрано 93 933 статьи за 2000-2026 годы: 1.1 ГБ текста и 8.3 ГБ изображений.

## Что получается

Один файл Markdown на статью, по пути `articles/ГГГГ/ММ/ДД/<slug>.md`:

```markdown
---
source: "https://novayagazeta.ru/articles/2012/01/23/47841-kapellan-otryada-bronehomyachkov"
title: "Капеллан отряда бронехомячков"
subtitle: ""
date: "2012-01-23T00:20:00Z"
authors: "Валерий Зеленогорский (писатель, блогер)"
rubric: "Политика"
genre: "Колонка"
tags: ""
---

# Капеллан отряда бронехомячков

Я этнически нерусский, грубо говоря - еврей, сетевой хомячище...
```

Изображения скачиваются отдельной стадией и вставляются в текст ссылкой на локальный файл. Ссылки внутри текста сохраняются обычными ссылками Markdown. Выноски становятся блоками `>`, редакционные пометки - подписанными цитатами, ссылки "читайте также" - отдельной строкой с URL, вставки видео и галерей - строкой с меткой сети и ссылкой.

Все поля шапки стоят в кавычках намеренно: заголовки часто содержат двоеточие с пробелом ("Суд Москвы: сенсация"), и без кавычек любой разборщик YAML обрежет значение на этом месте.

## Как это работает

Страница статьи несет всю запись целиком в виде URL-encoded JSON внутри `<script id="__SERVER_DATA__">`. Этот кусок меньше и заметно чище окружающего HTML, поэтому скрипты читают запись и рисуют Markdown сами, вместо того чтобы разбирать отрендеренный DOM. Отсюда отсутствие браузера, движка JS и сторонних пакетов: только стандартная библиотека Python.

Побочный выигрыш в скорости огромный. Playwright-скрапер вроде `md-scrape` поднимает браузер на каждую страницу, а здесь выходит около 14 запросов в секунду и 15 тысяч статей за 20 минут.

Если у записи пустое тело (так бывает у части старых статей), скрипт берет отрендеренный контейнер статьи, а потом поле `lead`, и оставляет тот вариант, где текста больше. Из контейнера при этом вырезаются блок донатов и контактная форма, иначе они утекают в текст.

## Требования

Python 3.8 или новее. Больше ничего, шага `pip install` нет.

## Порядок работы

Четыре стадии, все продолжаемые с места обрыва.

### 1. Сбор URL

```bash
python gather_urls.py                 # все источники
python gather_urls.py pdf sitemap     # быстрые, около 11 тысяч URL за 10 секунд
python gather_urls.py wayback --wayback-from 2019 --wayback-to 2021
```

Источники, от дешевых к дорогим:

| источник  | что дает                                                                  | скорость       |
| --------- | ------------------------------------------------------------------------- | -------------- |
| `sitemap` | `/feed/sitemap`, 1000 свежих статей                                       | секунды        |
| `pdf`     | открытый бакет GCS `novaya-static`, 10911 имен PDF равны слагам           | 10 секунд      |
| `cc`      | индекс Common Crawl, около 3 тысяч URL                                    | минуты         |
| `search`  | `/api/v1/search`, 20 записей на страницу, страницы 1-499 на каждый запрос | медленно       |
| `authors` | `/authors/<id>`, около 49 ссылок на автора, живых id примерно 153         | минуты         |
| `wayback` | CDX интернет-архива, один пагинированный запрос на год                    | очень медленно |

Полного индекса сайт не публикует. `/feed/sitemap` содержит ровно 1000 свежих статей и игнорирует параметры `from`, `to`, `page`, `limit`; `/feed/rss` содержит последние 100. Старые статьи отдаются, но недостижимы навигацией, поэтому историю приходится брать из Wayback.

Страница CDX готовится от 30 до 75 секунд, а их тысячи за 20 лет, так что `wayback` - самое узкое место. Его стоит запускать в фоне и дать накопить результаты в `gather_found.jsonl`. Повторный запуск любого источника добавляет только новое, так что коллекция только растет.

Главная ловушка: главная страница сайта - пустая оболочка, ссылки на статьи приходят из клиентского JS. Обход по ссылкам (breadth-first, как делает `md-scrape`) не находит вообще ничего, и на странице статьи тоже ровно одна внутренняя ссылка. Список URL обязателен.

Результат: `urls.txt` (отсортированный, без дублей) и `gather_found.jsonl` (какой источник что нашел).

### 2. Скачивание статей

```bash
python fetch_articles.py                  # все из urls.txt
python fetch_articles.py --limit 100      # проверка на выборке
python fetch_articles.py --workers 12 --rate 14
python fetch_articles.py --retry-missing  # только то, что упало
```

Прогресс пишется в `state.json`, а пропавшая запись состояния восстанавливается проверкой файла на диске, поэтому прерванный запуск ничего не теряет. Падения попадают в `failed.txt` с причиной.

### 3. Починка шапки, если понадобится

```bash
python fix_frontmatter.py --dry-run
python fix_frontmatter.py
```

Приводит поля YAML в кавычки прямо на диске, не перекачивая статьи. Пригодится, если шапку придется менять: 93 тысячи файлов чинятся за секунды вместо часов повторной загрузки.

### 4. Изображения

```bash
python fetch_assets.py --limit 20      # пробная партия
python fetch_assets.py                 # полный прогон, около 2.5 часов
python link_assets.py --dry-run        # посмотреть, что будет вставлено
python link_assets.py                  # вставить ссылки в Markdown
```

`fetch_assets.py` проходит по тому же `urls.txt` второй раз: в записи статьи каждый блок `image/single` несет поле `previewUrl`, а сам файл по этому адресу отдается как webp. Скрипт скачивает его в `articles/_assets/` и пишет карту в `assets_map.json`. Формат сохраняется исходный, ничего не конвертируется.

Имена файлов - md5 содержимого, первые два символа становятся подпапкой: `_assets/0f/0fc1e8a913d44b894f6ee567c6934afb.webp`. Так одно и то же фото, переиспользованное в десятках статей, хранится один раз и ни одна папка не держит сто тысяч файлов.

`link_assets.py` расставляет ссылки в готовых `.md`: находит строку-подпись под изображением и ставит картинку прямо перед ней, то есть там, где она была в оригинале.

```markdown
![](_assets/0f/0fc1e8a913d44b894f6ee567c6934afb.webp)

*Кадр из фильма «Отец мать сестра брат»*
```

Атрибут `alt` намеренно пустой: подпись уже стоит отдельной строкой под картинкой, и повторять ее в скобках значит дублировать текст. У части старых статей подписи в записи нет вообще, тогда описание ставится в `alt`, потому что больше его взять неоткуда.

У 8 645 статей подпись пустая, но изображение есть. Такие картинки, обычно лид-фото, ставятся сразу после заголовка `#`.

## Что показала практика

Из 122 951 адреса 93 945 отдали текст, 29 000 вернули 404 (умерли еще до закрытия), 6 оказались пустыми. Медиана файла 9 КБ, покрытие по годам ровное: 2006 - 3 488 статей, 2010 - 4 963, 2015 - 4 171, 2020 - 6 326, 2021 - 11 741, 2025 - 4 899, 2026 - 4 368.

Около 2 процентов файлов короче 1.2 КБ. Выборка из 25 таких файлов проверена заново: сайт действительно отдает там пару строк, это видеоанонсы, PDF-заглушки и отсылки вида "читайте в репортаже". Потерь тут нет.

## Замечания и ограничения

Wayback сохранял часть запросов относительных ассетов под видом статей, отсюда мусор вроде `/articles/2006/01/01/ic_mainLogo.svg`. Такие адреса отсекаются по расширению файла, всего отброшено 477.

Часть старых страниц содержит в ссылках логин и пароль вида `https://user:pass@host/...`. Учетные данные вычищаются из готового текста.

`robots.txt` запрещает `/api/`, `/hyper/` и `/preview/` для краулеров, страницы статей при этом разрешены. Источник `search` обращается к `/api/v1/search`, который под этот запрет попадает. Для личного архива это приемлемо, но если собираете не для себя, берите `wayback` и `pdf`.

Щадящий режим: сайту остались недели работы, и причин бить по нему нет. Здесь потолок проверен только снизу - фоновый прогон с 12 потоками и лимитом 14 запросов в секунду прошел 107 тысяч запросов без единого 429, но выше этого значения поведение не проверялось.
